# 온점. — 생각을 비우고, 한 걸음씩 나아가는 앱 🌿

**Codex 개발 시작용 독립 프로젝트 | v0.1 | 2026-11-03**

**현재 상태:** 모바일 우선 웹/PWA 프로토타입. 실제 동작 로직과 브라우저 저장을 구현했습니다. **네이티브 iOS/Android 앱 빌드, 실제 AI, 실광고, 인앱결제, 앱스토어 등록은 구현하지 않았습니다.**

## 빠르게 실행하기

Node.js 20 이상만 있으면 별도의 라이브러리 설치 없이 실행됩니다.

```bash
npm start
# 브라우저에서 http://localhost:4173 열기
npm test
```

> 로컬 서버를 실행할 PC나 개발 환경이 필요합니다. 파일을 아이폰에 바로 설치하는 앱(IPA)이 아닙니다. Codex/코딩 환경에 압축 파일을 전달해 작업을 이어갈 수 있습니다.

## 현재 구현된 사용자 흐름

1. **비우기** — 한국어 자유 텍스트/줄바꿈으로 여러 할 일을 입력합니다. 현재는 정규식 기반 분리이며 AI 호출이 아닙니다.
2. **한 걸음** — 활성 작업 1개를 크게 보여주고 완료/작게 나누기/나중에를 실행할 수 있습니다.
3. **성장** — 할 일 1개 완료마다 성장 1칸, 4개 완료하면 꽃 1송이 개화. 시간 측정이나 강제 출석은 없습니다.
4. **꽃** — 기본 12종, 특별 색상 변이, 크리스마스/할로윈/새해 시즌 꽃이 데이터로 정의되어 있습니다. 명절 추석은 음력 변동 때문에 실제 일정 소스 연동 전까지 미구현입니다.
5. **도감** — 최초 품종·색상 등록에 보상형 광고가 필요한 상태를 모의 처리하며, 기존 등록 꽃의 재개화는 광고 없이 등록합니다. 꽃말은 전통적 꽃말을 주장하지 않는 **온점. 창작 문구**입니다.
6. **보관** — 나중에 하기를 누르면 미완료 씨앗으로 보관되고, 다시 이어갈 수 있으며 시들거나 손해를 보지 않습니다.
7. **데이터** — localStorage 저장, 초기화 가능. 데모용 PLUS 토글은 실제 결제가 아닙니다.

## 설계 원칙

- 실행 흐름 우선, 꽃 성장·수집은 조용한 보조 동기입니다.
- 모든 생각 입력을 사용자 동의 없이 서버로 전송하지 않습니다.
- 작업 우선순위/기한/소요시간을 임의로 추정하거나 사실처럼 입력하지 않습니다.
- 꽃 개화 화면을 광고로 가리지 않습니다. **새 도감 항목을 사용자가 등록할 때만** 광고를 선택하도록 합니다.
- 광고 미시청·광고 재고 부족·오류 시 꽃을 잃지 않습니다.
- 같은 품종+색상의 도감 최초 등록 이후 동일 아이템에는 반복 광고를 요구하지 않습니다.
- 무료 사용자와 PLUS 사용자는 동일한 희귀 꽃 출현 확률을 가집니다.
- 꽃 성장·계절 테마·카드 저장은 무료입니다. 원칙적으로 강제 인터스티셜/배너 광고 없음.
- ADHD/치매 진단·치료 앱이 아닙니다. 의료적 효능 표현 금지.

## 구조

```
index.html                 # 모바일 우선 SPA 진입점
styles.css                 # 화면 스타일, 접근성, reduced-motion 대응
src/app.mjs                # 앱 화면, 이벤트, localStorage, 모달
src/logic.mjs              # 순수 도메인 규칙: 작업/성장/꽃/희귀도/등록
assets/icon.svg            # 자체 제작 앱 아이콘
manifest.webmanifest       # PWA 메타데이터
sw.js                      # 오프라인 캐시 (로컬 HTTP 환경)
server.mjs                 # 외부 의존성 없는 개발 서버
tests/logic.test.mjs       # Node.js 기본 테스트
AGENTS.md                  # Codex 프로젝트 가이드
CODEX_TASK.md              # 후속 개발 실행 프롬프트
```

## 주의 및 출시 전 필수 항목

- `src/logic.mjs`의 희귀도 (일반 96.5% / 특별 색 3% / 금빛 0.5%)와 시즌 개화 24%는 **테스트용 설계값**으로, 밸런싱 및 표시 방식 검토가 필요합니다.
- 모바일 앱용 광고는 AdMob 같은 보상형 광고 SDK, 광고 완료 검증, 광고 실패 처리, 중복 등록 방지, 보상 오남용 방지, 동의/개인정보 처리가 필요합니다.
- PLUS는 결제·구독·영수증 검증이 전혀 없는 데모 토글입니다. 실제 출시에서는 App Store/Google Play IAP와 서버 검증으로 교체해야 합니다.
- 실제 AI 작업 분리는 서버 프록시 + 명시적 동의 + 데이터 최소화 + 사용량 제한과 함께 붙여야 합니다. API 키를 모바일 클라이언트에 넣지 마세요.
- 현 상태 localStorage는 보안 저장소가 아니므로 개인의 의료/건강 정보 등 민감정보를 입력하도록 유도하지 마세요.
- 추석은 음력 명절이며 매년 달라집니다. 달력 API 또는 연도별 공식 일정 테이블을 사용해야 합니다.
- 꽃 수집·보상 광고가 갖는 정책 의무와 확률형 상품 규제는 최종 유료화 구조에 맞춰 다시 검토해야 합니다.
