# 온점. 화면 구조 검토 · 2026-11-04

사용자 요청: 모바일 블로그처럼 이어지는 화면을 앱다운 UI/UX와 공간감으로 다시 구성하고, 정원은 3×3 넘기기를 유지한다.

## 조사 범위와 제약

다음 공식 주소에 실제 접속을 시도했지만 실행 환경 프록시의 HTTP403 정책 거부로 페이지/스크린샷을 읽지 못했다. 따라서 최신 버전의 세부 화면·애니메이션·과금 동선을 조사 완료했다고 주장하지 않는다. 설치·사용·사용성 인터뷰도 수행하지 않았다.

| 비교 후보               | 공식 주소                                                               | 이번 작업에서 확인한 범위   |
| ----------------------- | ----------------------------------------------------------------------- | --------------------------- |
| Forest                  | https://www.forestapp.cc/                                               | 접속 차단, 최신 화면 미확인 |
| Finch                   | https://finchcare.com/                                                  | 접속 차단, 최신 화면 미확인 |
| Structured              | https://structured.app/                                                 | 접속 차단, 최신 화면 미확인 |

위 서비스는 향후 비교 대상이며 아래 결정의 직접 검증 출처가 아니다. 공식 페이지 접근에 필요한 호스트를 기존 네트워크 초안에 추가했다. 초안 저장은 현재 환경의 접근 허용과 다르다. 사용자가 환경 설정을 저장하고 게시한 뒤 공식 페이지를 재조사해야 한다. 다른 앱의 캐릭터·일러스트·화면을 복제하지 않았다.

## 이번에 적용한 자체 설계

| 기존 문제                                       | 변경                                                 | 사용자에게 주는 결과                             |
| ----------------------------------------------- | ---------------------------------------------------- | ------------------------------------------------ |
| 제목·그림·통계·카드가 독립적인 글 묶음처럼 보임 | 홈을 하나의 온실 장면과 겹친 행동 패널로 구성        | 무엇을 누를지 먼저 보임                          |
| 정원에서 꽃 하나마다 사각 카드가 둘러쌈         | 세 줄 선반·곡면 화분·접촉 그림자, 페이지마다 9자리   | 수집 목록 대신 꽃이 놓인 공간으로 읽힘           |
| 실행 화면에서 모든 버튼의 비중이 비슷함         | 완료를 유일한 주 버튼으로, 나중에/나누기는 보조 줄로 | 한 가지 행동에 집중                              |
| 중앙 모달이 작은 화면을 좁힘                    | 안전 영역을 고려한 하단 시트·스크롤·44px 닫기        | 손 닿는 위치에서 입력/검토/상세 조작             |
| 개화가 긴 설명 화면에 섞임                      | 조명 배경·꽃·중앙 꽃말·별도 기억 기록                | 꽃을 발견하는 순간에 시선 집중                   |
| 작은 화면에서 주 행동이 아래로 밀림             | 화면 높이에 맞춰 장면 높이 조절                      | 320×640에서도 짧은 제목의 주 버튼이 탭 위에 노출 |

2.5D 표현은 SVG 그라데이션, 원근 받침대, 선반 앞면, 그림자를 사용한다. WebGL/3D 모델, 원격 이미지·폰트, 새로운 의존성은 없다. 선택 피드백은 짧은 눌림 상태이며 개화 페이드만 모션 설정에 따라 사용한다. 타이머·연속 출석·시들기·추가 광고 유도는 도입하지 않는다.

## 검증과 다음 조사

실제 React Native 웹 화면의 입력→검토→한 가지 실행→개화→꽃 상세, 광고 취소/등록, 씨앗 복원, 백업/복원, 오프라인 재실행을 자동 조작한다. 추가로 하단 시트 위치, 닫기 후 초안 유지, 홈 이어 하기, 작은 단계 전환과 320px 주 버튼 위치를 검사한다. 스크린샷도 직접 검토한다. 테스트 수와 최종 실행 결과는 루트 VALIDATION.md를 따른다.

브라우저 자동 검증은 실제 사용자 평가나 iOS/Android 실기기 검증을 대체하지 않는다. 다음은 공식 화면 접근 후 정보 위계·첫 실행 동선·오류/복구·동작 감소·접근성 비교, 실물 Safari 안전 영역/키보드/터치 넘기기, 긴 한국어 제목 및 시스템 큰 글꼴/VoiceOver 검증이다. 이번에는 데이터 모델·성장/희귀 확률·SQLite 형식·원본 프로토타입을 바꾸지 않았다.
