# 온점.

복잡한 생각을 자유롭게 내려놓고 하나씩 실제 행동으로 옮기는 한국어 감성 실행 앱입니다. 꽃을 키우려고 일을 하는 것이 아니라, 하루를 조금씩 정리했더니 어느새 꽃이 피어납니다.

React Native / Expo SDK 54 기반 iOS·Android 앱과 HTML/CSS/JavaScript PWA 프로토타입이 같은 순수 도메인 로직을 사용합니다. ADHD 치료, 집중 타이머, 연속 출석, 식물 시들기, 미완료 페널티는 없습니다.

> 개발 시작 당시 로컬 및 원격 main에는 제목만 있는 README만 있었습니다. 지시서에서 언급한 기존 웹·AGENTS.md·CODEX_NEXT_PROMPT.md·src/logic.mjs·테스트는 제공되지 않아 이 구현을 새로 작성했습니다. 과거 대화의 원본 구현과의 호환성은 확인되지 않았습니다. 기존 파일을 받으면 덮어쓰지 말고 비교·통합해야 합니다.

## 실행

Node.js 22.13 이상(검증: 24.19), npm을 사용합니다.

```sh
npm ci
npm start
```

Expo SDK 54를 지원하는 Expo Go 또는 개발 빌드에서 실행합니다. iOS 시뮬레이터는 macOS/Xcode, Android 에뮬레이터는 Android SDK가 필요합니다. 최신 Expo Go가 SDK 54를 지원하지 않으면 SDK 54용 개발 빌드를 사용하거나 별도 작업으로 SDK를 업그레이드하세요.

```sh
npm run ios       # iOS 시뮬레이터
npm run android   # Android 에뮬레이터/연결된 기기
npm run web       # 별도 HTML PWA (기본 포트 4173)
```

Expo 모바일의 SQLite 코드는 네이티브 전용입니다. 브라우저에서는 `npm run web`으로 표시되는 웹 프로토타입을 사용하세요. PWA는 localStorage와 서비스 워커를 사용합니다. 오프라인은 최초 온라인 방문 및 캐싱 후 작동하며 브라우저에 따라 설치 지원이 다릅니다. 웹과 모바일은 공통 JSON 백업으로 수동 이동할 수 있지만 자동 동기화되지는 않습니다. 저장소 전체를 웹 루트로 공개하지 않고 `web/` 및 공용 로직만 제공하는 개발 서버를 사용합니다.

## 사용 흐름

- **오늘**: 자유롭게 생각 입력 → 규칙 기반 분리 → 사용자가 수정/제외/추가 → 확정. 실제 AI라고 표시하지 않습니다. `src/separator.mjs`의 비동기 `separate(text)` 인터페이스를 향후 서버 어댑터로 교체할 수 있습니다.
- **실행**: 할 일 하나만 표시합니다. 완료, 나중에 하기(순서 뒤로), 작은 단계로 교체, 씨앗 보관을 선택합니다.
- **개화**: 실제 완료 4개마다 꽃 1송이가 생깁니다. 기본 12종, 일반 색상 2종과 희귀 보라색(5%)입니다. 유료 여부는 추첨 입력에 관여하지 않습니다.
- **시즌**: 한국 날짜 기준 크리스마스 12/20–26, 할로윈 10/25–31, 새해 1/1–7, 추석 음력 8/14–16에는 시즌 꽃을 만납니다. 추석은 ICU 중국력 변환을 사용합니다. 현대 한국 음력과 다른 역사적 날짜 및 기기별 ICU 지원은 별도 검증이 필요합니다.
- **정원**: 계절별 배경, 최근 꽃, 모든 꽃을 보관하는 기억의 정원, 품종·색상별 꽃말/개화일/네 행동 기록을 보여 주는 도감입니다. 미등록 꽃도 저장되며 소멸하지 않습니다.
- **씨앗**: 보관한 미완료 할 일을 복원합니다. 보관/복원/나중에 하기 자체로는 성장하지 않습니다.
- **설정**: 모션 감소(기기 설정도 적용), PLUS 테스트, 파일 백업/복원/전체 삭제를 제공합니다.

## 광고·PLUS는 테스트 전용

실제 광고/결제 SDK, 서버 검증, 구매 복원은 연결하지 않았습니다. 비용은 청구되지 않으며 설정과 보상 화면에 테스트 모드가 명시됩니다. 무료 사용자가 새 품종·색상 조합을 **처음 등록**할 때만 선택형 보상 테스트를 거칩니다. 동일 조합 중복 및 PLUS 테스트는 광고 없이 등록합니다. 취소·미제공 시 미등록 상태 그대로 영구 보관합니다. 테스트 버튼은 실제 보상 증명이 아니며 출시 전 제거하고 서버 검증과 실제 구매 권한으로 교체해야 합니다.

## 저장·복구

모바일 `onjeom.db`는 `expo-sqlite`의 WAL / FULL synchronous 및 배타적 트랜잭션을 사용합니다. UI는 저장 성공 후에만 상태를 반영하며 저장 실패 시 오류를 표시합니다. 연속 입력 저장을 잠가 중복 완료를 방지합니다.

SQLite `user_version` 0 → 1(상태 테이블) → 2(메타데이터 테이블 및 payload 마이그레이션)를 원자적으로 수행합니다. 미래 버전과 손상된 데이터는 자동 초기화하지 않고 오류로 보존합니다. payload v1 → v2 마이그레이션은 **이 구현이 정의한 형식**이며, 제공되지 않은 과거 프로토타입의 임의 형식을 지원한다는 뜻이 아닙니다.

설정에서 백업 파일을 공유하여 기기 밖에 보관할 수 있습니다. 복원은 확인 후 현재 데이터를 대체하고 버전·ID·날짜·품종·성취 수의 일관성을 검증한 뒤 저장합니다. 잘못된 백업은 현재 데이터를 변경하지 않습니다. 전체 삭제는 DB 상태를 초기화하고 WAL 체크포인트와 VACUUM을 수행합니다. OS 백업/플래시 수준의 보안 삭제를 보장하지 않습니다. 내보낸 백업 파일은 별도 삭제해야 합니다.

백업은 암호화하지 않은 JSON이며 개인 생각과 성취 기록을 포함합니다. 현재 앱은 서버에 전송하지 않습니다. 모바일 앱 강제 종료 후 미확정 생각 초안/분리 검토 중 입력은 복원하지 않고, 확정된 할 일과 꽃·설정은 복원합니다.

## 검증

```sh
npm test               # Node 내장 테스트 + 실제 SQLite 파일 재오픈
npm run check          # TypeScript 앱 타입 검사
npm run export         # iOS·Android Hermes 번들 생성 (서명 APK/IPA 아님)
npm run test:browser   # Chromium 실제 웹 흐름
```

브라우저 테스트는 Linux의 `/usr/bin/chromium`을 기본으로 사용합니다. 다른 설치 위치는 `CHROMIUM_PATH`로 지정하세요. 환경에 브라우저가 없다면 Chromium을 설치한 뒤 실행하세요. 테스트 서버는 자동 시작·종료됩니다.

실행한 결과:

- 도메인/SQLite 테스트 **16개 통과**: 4회 완료, 12종, 희귀 확률 경계와 PLUS 동일성, 시즌 경계/한국 날짜, 씨앗 복원, 단계 분리, 광고 취소/미제공/중복 등록, 백업 손상 거절, DB 재오픈 복원, v1→v2 및 실패 롤백.
- `npm run check` 통과.
- iOS·Android Metro/Hermes 번들 생성 통과.
- 브라우저 결과는 `VALIDATION.md` 참고.

실행하지 못한 검사: iOS·Android 실기기/시뮬레이터 UI, 네이티브 공유·파일 선택, 기기 재부팅 후 복원, VoiceOver/TalkBack·큰 글꼴, App Store/Play Store 배포. SQLite 파일 재오픈 테스트는 프로세스 재시작 저장 계층을 검증하며 실제 네이티브 앱 강제 종료 테스트를 대신하지 않습니다.

## 구조와 남은 작업

- `App.tsx`: 모바일 UI 및 저장/백업 연결
- `src/logic.mjs`: 도메인, 데이터 검증, 백업, 계절
- `src/storage.mjs`: SQLite 어댑터 및 DB 마이그레이션
- `src/separator.mjs`: 규칙 분리 인터페이스
- `web/`: 별도 PWA / `tests/`: 도메인·SQLite·브라우저 테스트
