# 온점.

현재 웹앱 주소: **https://shindongus.github.io/onjeom/**

최신 화면은 입체적인 작은 온실, 하단 행동 패널, 한 가지 실행 화면, 3×3 화분 선반 정원으로 구성합니다. 기존 배포 주소에 업데이트하며 최신 게시 검증은 `.github/pages-live-status.json`에서 확인합니다.

2026-11-04 GitHub Pages가 `gh-pages / (root)`에서 배포 완료된 것을 확인했고, GitHub의 검증 작업에서 앱 HTML·웹 번들·설치 스크립트·매니페스트·Apple Touch 아이콘·서비스 워커가 모두 HTTP200으로 응답했습니다. 아이폰 Safari에서 열어 공유 → 홈 화면에 추가로 설치할 수 있습니다. 실물 아이폰 설치 자체는 별도 확인이 필요합니다. 아래의 초기 설정 실패 기록은 활성화 이전 상황입니다.

생각을 자유롭게 내려놓고 하나씩 실제 행동으로 옮기면 어느새 꽃이 피어나는 한국어 실행 앱입니다. 치료·진단, 집중 타이머, 연속 출석, 식물 시들기, 미완료 페널티는 없습니다.

React Native / Expo 모바일 앱과 원본을 바탕으로 한 HTML/PWA가 순수 도메인 로직을 공유합니다. 첨부받은 `onjeom-codex-ready.zip`은 **`prototype/`에 모든 파일을 바이트 그대로 보존**했습니다. `prototype-source.json`의 SHA-256을 자동 테스트로 검증합니다. 원본 지침은 루트 `AGENTS.md`에도 적용합니다.

## 실행

Node.js 22.13 이상, npm. 검증 환경은 Linux / Node 24.19 / Expo SDK 54입니다.

```sh
npm ci
npm start                  # Expo 개발 서버
npm run ios                # 호환 iOS 시뮬레이터에서 열기 (macOS/Xcode 필요)
npm run android            # Android 에뮬레이터/연결 기기에서 열기
npm run build:ios          # 네이티브 개발 빌드 생성·실행 (macOS/Xcode 필요)
npm run build:android      # 네이티브 개발 빌드 생성·실행 (Android SDK 필요)
npm run web                # 통합한 원본 기반 웹, 기본 포트 4173
npm run mobile:web         # 실제 React Native UI의 브라우저 미리보기
npm run export:preview     # React Native 웹 정적 번들 생성
npm run preview:mobile     # 생성한 미리보기 실행, 기본 포트 4174
```

Expo SDK 54와 호환되는 Expo Go 또는 개발 빌드를 사용합니다. 최신 Expo Go의 SDK 지원 범위와는 다를 수 있습니다. 기존 검증된 SDK 54를 유지했으며 이번 통합에서 최신 SDK 업그레이드나 스토어 배포는 수행하지 않았습니다. 모바일 SQLite는 iOS·Android 전용입니다. `npm run web`은 원본 기반 PWA이고 `npm run mobile:web`은 **같은 App.tsx를 실행하는 React Native 브라우저 미리보기**입니다. 미리보기는 별도 IndexedDB에 저장하고 파일 다운로드/선택을 브라우저 API로 처리합니다. 원본 PWA·브라우저 미리보기·실기기 데이터는 자동 동기화되지 않으며 JSON 백업으로 옮깁니다.

`npm run prototype:original`은 **수정 없는 보존본**을 실행합니다. 원본에는 모달의 인라인 `stopPropagation()` 때문에 내부 버튼이 문서 이벤트 처리기로 전달되지 않는 문제가 있습니다. 기본 `npm run web`은 이 문제를 고친 실행용 `web/app.mjs`를 사용합니다. 원본 CSS·일러스트·도메인은 유지하고 검토·수정·순서 변경과 백업 전환을 보완했습니다. 두 서버의 기본 포트가 같으므로 동시에 실행하지 마세요.

## 제품 흐름과 원본 규칙

- **생각 입력 → 사용자 검토**: 원본의 한국어 규칙 기반 `splitThought`를 공유합니다. AI가 아닙니다. 분리 결과의 수정·제외·추가·순서 변경 후 확정하며, 검토한 제목을 다시 파싱하지 않습니다. 입력하지 않은 기한·우선순위·예상 시간을 추가하지 않습니다.
- **한 번에 하나**: 완료, 나중에, 작은 단계로 나누기. 나중에는 원본처럼 씨앗 보관함으로 이동하고 이어하면 활성 목록 끝에 돌아옵니다. 모바일 ‘오늘’의 할 일 관리에서 제목 수정·삭제·순서 변경도 가능합니다.
- **4개 완료 → 1송이 개화**: 원본 12종과 창작 문구를 유지합니다. 개발용 확률은 일반 96.5%, 달빛·오로라 합계 3%, 금빛 0.5%. 무료와 PLUS가 같은 추첨을 사용합니다.
- **시즌**: 원본대로 크리스마스 12/18–26, 할로윈 10/24–11/1, 새해 12/30–1/3. 기간 중 시즌 품종 확률은 24%이며, 항상 시즌 품종만 나오는 구조가 아닙니다. 날짜는 원본처럼 기기 현지 날짜를 사용합니다.
- **추석은 아직 비활성**: `src/season-calendar.mjs`에 출처가 검토된 연도별 공식 양력 일정이 있을 때만 활성화됩니다. 한국천문연구원 접근이 현재 네트워크 정책에서 HTTP 403으로 차단되어 공식 데이터를 검증하지 못했습니다. 음력 추정이나 임의 날짜를 넣지 않았습니다. 테스트의 가상 일정은 실제 운영 데이터가 아닙니다.
- **꽃말은 온점. 창작 문구**: 전통 꽃말/식물학적 사실로 표시하지 않습니다. 등록 전에도 열람과 **일러스트가 포함된 SVG 꽃말 카드** 저장/공유가 무료입니다. SVG는 글자와 꽃 그림을 함께 담은 파일이며 외부 리소스를 불러오지 않습니다. 웹은 무료 카드 문구 복사를 제공합니다. 모바일 네이티브 공유는 실기기에서 추가 검증해야 합니다.
- **정원·도감**: 계절 배경과 모든 꽃의 기억의 정원, 품종+색상별 도감, 개화일·완료 행동 기록. 미등록 꽃도 계속 보관합니다. 새 꽃에는 최근 네 완료 행동을 기록하고, 원본에서 가져온 꽃에는 원래 있던 `originTask`만 보여 줍니다. 없는 과거 기록을 만들어 내지 않습니다.

## 광고·PLUS·AI 경계

실제 광고/결제 SDK·구매 권한 검증은 없습니다. 모든 관련 화면에 테스트 모드를 표시하고 비용을 청구하지 않습니다. 무료 사용자가 **새 품종+색상 조합을 최초 등록하기로 선택한 순간에만** 보상 테스트를 제안합니다. 동일 조합은 광고 없이 등록하며 PLUS 데모도 우회합니다. 취소·미제공은 미등록 꽃을 유지합니다. 개화와 꽃말 카드에는 광고가 없습니다.

실제 SDK 연결 전에는 테스트 성공 버튼을 실제 보상 증거로 사용하지 마세요. AI 서버는 연결하지 않았습니다. `src/separator.mjs`의 비동기 `separate(text)`를 향후 동의·서버 인증·오류 처리를 갖춘 어댑터로 교체할 수 있습니다. 작업 원문을 광고/분석에 보내지 않습니다.

## 원본 웹 기록을 모바일로 옮기기

1. 원본을 사용하던 **같은 브라우저·호스트·포트**에서 통합 웹을 실행합니다. 저장 키 `onjeom.local.v1`을 그대로 사용하므로 기존 웹 기록을 이어서 볼 수 있습니다.
2. 보관함의 ‘백업 내보내기 · 모바일로 옮기기’를 열거나 `/transfer/` 경로를 엽니다.
3. ‘이 브라우저 기록 내보내기’로 JSON을 저장하고 모바일 설정에서 그 파일을 복원합니다. 웹의 원본 저장소는 변경하지 않습니다.

다른 사이트/브라우저의 localStorage는 읽을 수 없습니다. 다른 호스트에서 사용한 원본은 해당 사이트의 기록 JSON을 확보해 전환 화면의 파일 선택으로 변환해야 합니다. 기기 간 자동 동기화나 계정 로그인은 없습니다. 백업은 개인 생각을 포함하는 **암호화하지 않은 JSON**이므로 안전한 곳에 보관하세요.

## SQLite 및 마이그레이션

`onjeom.db`는 WAL·FULL synchronous·배타적 트랜잭션을 사용하며 저장 성공 후 UI를 반영합니다. DB `user_version`은 0→1(상태 테이블)→2(메타데이터)→3(원본 공유 스키마)으로 이동합니다.

지원하는 입력은 원본 웹 v1 JSON, 앞서 만든 모바일 v1/v2 JSON 백업, 현재 v3 백업입니다. 원본의 생각 원문·작업 ID/순서·미완료 씨앗·꽃 ID/색상/창작 문구/날짜/등록 여부를 유지합니다. 앞선 모바일의 다른 꽃·색상도 `legacy-*` 변이로 보관하며 새 추첨에는 원본 규칙만 씁니다. v2에 없던 생각 원문이나 정확한 생성 시간은 새로 만들지 않습니다.

버전·ID·날짜·종류·진행 수를 검사해 손상/미래 버전 데이터를 자동 초기화하지 않습니다. 실패한 마이그레이션은 롤백하고 잘못된 복원은 기존 데이터를 바꾸지 않습니다. 손상된 구버전 payload도 시작 오류 화면에서 **유효 백업을 선택하고 복원을 확인한 경우에만** 교체합니다. DB 파일 자체 손상·누락을 모두 수리하는 기능은 아니므로 기기 밖 백업이 필요합니다.

복원은 현재 기기 전체 상태를 교체합니다. 전체 삭제는 빈 상태 저장 후 WAL 체크포인트/VACUUM을 실행합니다. 플래시나 OS 백업까지의 보안 삭제를 보장하지 않으며 내보낸 파일은 별도 삭제해야 합니다. 앱 중단 시 확정한 작업/꽃/설정은 복원하지만 미확정 입력 초안은 복원하지 않습니다.

## 검증

```sh
npm test                   # 원본 11개 포함 총 31개 도메인/SQLite/무결성 테스트
npm run test:original       # 첨부 원본 테스트 11개 그대로 실행
npm run test:browser        # 원본 기반 PWA 사용자 흐름 4개
npm run test:mobile         # 실제 React Native UI·PWA 사용자 흐름 6개 (웹 번들 자동 생성)
npm run check              # TypeScript
npm run format:check       # 원본 폴더는 포맷 대상에서 제외
npm run export             # iOS·Android Hermes 번들, 설치 파일은 아님
```

Chromium 기본 경로는 `/usr/bin/chromium`이며 `CHROMIUM_PATH`로 변경할 수 있습니다. React Native UI 테스트는 390×844 및 320×640에서 생각 검토→개화→무료 카드→취소/등록→재접속→씨앗→백업·삭제·복원을 실제 화면 조작으로 확인합니다. 모션 감소, 손상 백업 거절, 원본 웹 JSON 복원·삭제 취소도 검증합니다. 스크린샷은 `artifacts/mobile-today.png`, `mobile-bloom.png`, `mobile-garden.png`에 생성합니다. 자세한 실행 결과와 미실행 항목은 `VALIDATION.md`를 확인하세요. React Native 브라우저 검증은 네이티브 런타임 검증을 대신하지 않습니다. 실기기의 파일 공유/선택·접근성·스토어 배포는 QA가 남아 있습니다. Node SQLite 파일 재오픈 검증을 실제 모바일 재부팅 검증으로 간주하지 않습니다.

## 모바일 화면과 일러스트

기본 12종마다 다른 벡터 형태를 사용하며 시즌 품종과 기존 색상 변이를 같은 렌더러로 표현합니다. 수선화·수국·라벤더·안개꽃 등은 형태가 구별되며 실제 식물 동정용 그림은 아닙니다. 성장 0~3단계는 씨앗·새싹·잎·봉오리로 표시하고 개화는 실제 완료 4회에서만 발생합니다.

계절별 정원에 현재 화분과 최근 꽃을 보여 주고, ‘기억의 정원’과 ‘꽃 도감’을 선택할 수 있습니다. 탭 전환 시 스크롤을 맨 위로 돌립니다. 모달은 작은 화면에서 스크롤할 수 있고 iOS 키보드 회피를 적용했습니다. 개화의 짧은 페이드는 앱과 기기 모션 감소 설정을 따릅니다.

## 아이폰 홈 화면에 설치하기

React Native 웹앱에 설치용 매니페스트, 180px Apple Touch 아이콘, 192/512px 아이콘과 오프라인 앱 셸을 포함했습니다. 앱을 열어 한 번 캐싱한 뒤에는 네트워크가 없어도 기기 내 기록을 읽고 작업을 완료·저장할 수 있습니다. 업데이트는 열린 앱을 강제로 새로고침하지 않고 기존 창을 닫은 뒤 적용합니다.

설치하려면 **HTTPS 공개 주소로 먼저 배포**해야 합니다. `npm run export:preview`로 생성한 `dist-preview/` 전체가 정적 호스팅의 웹 루트에 있어야 합니다. `npm run export:preview`는 도메인 루트용이고 `npm run export:pages`는 GitHub Pages `/onjeom/` 경로용입니다. `app.config.ts`가 Expo의 baseUrl을 호스팅 경로에 맞게 설정하며 아이콘·설치 스크립트·오프라인 셸도 같은 경로를 사용합니다. 배포 파일은 `gh-pages` 브랜치에 업로드했고 2026-11-04 Pages 활성화와 실제 사이트의 필수 파일 응답을 확인했습니다. TestFlight 초대 링크나 서명된 iOS 설치 파일은 없습니다.

배포 주소가 생기면 아이폰 **Safari로 열기 → 공유 → 홈 화면에 추가 → 추가** 순서로 설치합니다. Apple Developer 계정 없이 사용할 수 있는 웹앱 방식입니다. TestFlight/App Store의 네이티브 앱을 원하면 Apple Developer 서명과 별도 배포가 필요합니다.

Safari와 홈 화면 앱 사이의 저장소 공유는 iOS 버전에 따라 다를 수 있으므로 홈 화면에 추가한 뒤 그 앱에서 사용하기를 권장합니다. 기존 기록이 있다면 먼저 JSON 백업을 내보내세요. 저장소/홈 화면 앱 삭제 시 기록을 잃을 수 있어 기기 밖 백업이 필요합니다. 실제 아이폰 설치는 미검증이며 Chromium에서 설치 메타데이터·오프라인 재접속·완료 후 재실행 저장을 검증했습니다.

배포용 압축 파일은 `artifacts/onjeom-iphone-web.zip`에 만들 수 있습니다. 이 ZIP 자체는 아이폰에 직접 설치하는 앱 파일이 아닙니다.

## GitHub Pages로 아이폰 설치 링크 만들기

```sh
npm run test:pages           # /onjeom/ 경로의 설치·오프라인 검증
npm run publish:pages        # Pages용 빌드 후 origin의 gh-pages 브랜치에 업로드
```

게시 스크립트는 원본 저장소가 ShinDongus/onjeom인지 확인하고 임시 Git 인덱스로 빌드 파일만 배포합니다. 기존 인덱스와 소스 체크아웃을 바꾸지 않으며 배포 브랜치를 강제 푸시하지 않습니다. `.nojekyll`을 포함해 Expo의 `_expo` 자산이 그대로 제공되도록 합니다. 이 명령은 정적 앱을 외부 저장소에 올리는 실제 게시 작업입니다.

최초 한 번은 [저장소 Pages 설정](https://github.com/ShinDongus/onjeom/settings/pages)에서 **Source: Deploy from a branch → Branch: gh-pages / (root) → Save**를 선택해야 합니다. GitHub의 게시 작업이 성공한 후 예상 앱 주소는 **https://shindongus.github.io/onjeom/** 입니다. 이 주소를 아이폰 Safari에서 열고 공유 → 홈 화면에 추가로 설치합니다. 저장소가 비공개인 경우 GitHub 요금제에 따라 Pages 사용이 제한될 수 있으며 저장소 공개 여부를 자동으로 바꾸지는 않습니다.

현재 환경에서는 저장소 Git 읽기·쓰기는 되지만 `api.github.com` 및 `shindongus.github.io`가 네트워크 정책에서 차단되어 Pages 활성화와 실제 공개 사이트 응답을 확인하지 못했습니다. 필요한 두 도메인을 기존 허용 목록에 보존·추가하는 환경 초안을 저장했습니다. GitHub의 Pages 활성화와 클라우드 환경의 네트워크 설정 게시를 구분하세요. 아이폰은 이 실행 환경의 네트워크 정책을 사용하지 않습니다.

## 초기 Pages 자동 설정 기록 (현재 사이트는 활성화됨)

`.github/workflows/configure-pages.yml`은 GitHub에서 Pages를 `gh-pages / (root)`로 설정하고 빌드·실제 HTML·설치 매니페스트까지 확인합니다. 결과는 `.github/pages-status.json`에 기록합니다. 기존 사이트가 없으면 생성도 시도하되 GitHub가 허용한 권한 안에서만 수행합니다.

실행 41661230637은 Pages 생성 단계에서 GitHub의 **403 Resource not accessible by integration**으로 실패했습니다. 이 기록은 초기 자동 생성 시도에 대한 실패이며, 이후 사용자가 설정한 Pages는 2026-11-04 실제 접속 검증을 통과했습니다. 로컬 네트워크 차단과 별개로 GitHub 자동화 인증에 사이트 생성 권한이 부족하다는 서버 응답을 확인했습니다.

향후 별도 사이트 자동 생성에 관리 인증이 필요한 경우 저장소의 Actions secret `PAGES_TOKEN`에 해당 저장소만 접근하는 GitHub 인증을 안전하게 등록할 수 있습니다. fine-grained PAT의 경우 Pages 읽기/쓰기와 검증에 필요한 Contents 읽기 권한이 필요합니다. GitHub App 인증은 Pages/Administration 관리 권한이 필요합니다. 실제 토큰 값은 채팅·코드·Git 기록에 넣지 않습니다. 인증이 준비되면 워크플로우를 다시 실행해 설정과 실제 주소를 검증해야 합니다. GitHub의 기본 워크플로우 토큰만으로 사이트 생성 권한을 임의로 늘릴 수는 없습니다.

## Android 테스트 APK 빌드

`npm run apk:android`는 arm64 기기용 로컬 미리보기 APK를 만드는 명령입니다. JDK17, Android API36, build-tools36.0.0, NDK27.1.12297006, CMake3.22.1과 `JAVA_HOME`·`ANDROID_HOME`(또는 `ANDROID_SDK_ROOT`)이 필요합니다. Android CLI 설치 예시는 다음과 같습니다.

```sh
android --no-metrics sdk install platforms/android-36 build-tools/36.0.0 platform-tools ndk/27.1.12297006 cmake/3.22.1
npm run apk:android
```

스크립트는 Expo prebuild 후 arm64 Release 변형을 컴파일하고 APK 서명을 검증합니다. 기본 생성 프로젝트의 디버그 키로 서명하는 **테스트용 빌드**이며 스토어 배포용 서명·등록을 수행하지 않습니다. 성공 시 `artifacts/onjeom-preview-arm64.apk`와 SHA256 파일을 만듭니다. Gradle8.14.3의 공식 SHA256을 검증하며, 네트워크 프록시가 있으면 기존 `HTTPS_PROXY`/`HTTP_PROXY`의 경로를 사용합니다. 별도 CA가 필요한 환경에서는 신뢰할 수 있는 Java truststore 경로를 `ONJEOM_GRADLE_TRUST_STORE`로 지정할 수 있습니다. TLS 검증을 끄지 않습니다.

**현재 APK는 생성되지 않았습니다.** 이 환경에서 SDK와 JDK를 설치하고 실제 네이티브 빌드를 시도했지만, Maven의 React Native 바이너리 리다이렉트 주소 `repo.reactnative.dev`가 네트워크 정책에서 403으로 차단됐습니다. 해당 주소와 공식 추석 자료용 `astro.kasi.re.kr`만 허용하는 환경 설정 초안을 저장했습니다. 환경 설정에서 변경을 검토·저장하고 환경을 게시한 뒤 빌드를 다시 실행해야 합니다. 초안 저장만으로 현재 실행 환경의 네트워크가 바뀌지는 않습니다.

표시 이름 `온점.`은 유지하면서 Gradle 내부 프로젝트 이름만 `Onjeom`으로 정하는 `plugins/withAndroidProjectName.cjs`를 적용했습니다. 마침표로 끝나는 Gradle 프로젝트 이름 때문에 네이티브 빌드가 실패하는 문제를 해결하는 설정이며 prebuild 때 재적용됩니다. 생성된 `android/`와 빌드 결과는 Git에 넣지 않습니다.

## 주요 파일과 남은 작업

`prototype/`는 수정 없는 첨부 원본, `src/logic.mjs`는 그 도메인을 재노출하는 공유 진입점, `src/mobile-domain.mjs`는 검토/스키마/백업 확장입니다. `src/legacy-mobile.mjs`는 이전 모바일 데이터 읽기 전용이고 새 작업 규칙으로 사용하지 않습니다. `App.tsx`는 Expo UI, `src/storage.mjs`는 SQLite, `web/`는 원본 기반 실행 UI·전환 도구입니다. `src/components/`는 정원·꽃·공통 시트, `flower-art.mjs`/`flower-card.mjs`는 벡터 그림과 무료 카드, `platform-store`/`device-files`의 플랫폼별 파일은 SQLite·공유와 브라우저 미리보기의 저장·다운로드를 연결합니다.

남은 작업: 공식 추석 일정 검증·등록, 실기기 QA와 큰 글꼴/VoiceOver/TalkBack, 긴 기록 목록 가상화, 최신 Expo SDK 업그레이드/개발 빌드 호환성 확인, 실제 광고/결제 서버 검증과 스토어 설정. 원본 아카이브의 설명은 당시 상태를 기록하므로 현재 기능은 이 README를 기준으로 봅니다.

## 모바일 화면 개편 — 2026-11-04

첫 화면은 화분·현재 할 일 한 가지·생각 꺼내놓기 버튼으로 구성합니다. 긴 입력 폼은 시트에서 열고, 규칙 분리 결과를 직접 검토한 뒤 확정합니다. 모바일 너비를 유지하는 앱 프레임과 아이콘 탭을 사용합니다.

정원과 도감은 한 페이지에 3×3, 총 9칸입니다. 좌우 스크롤/스와이프 및 이전·다음 버튼으로 이동하며 마지막 페이지의 남는 칸과 빈 정원도 빈자리로 표시합니다. FlatList로 주변 페이지만 렌더링합니다. 꽃을 누르면 꽃말·개화일·원래 행동·무료 카드·선택형 도감 등록이 열립니다. 도감 등록 여부는 격자의 작은 표식으로 확인합니다.

원본 도메인·백업 형식·SQLite 스키마는 바꾸지 않습니다. UI 테스트는 새 입력 시트 경로, 9+3송이 두 페이지, 빈자리, 페이지 이동/가로 스크롤, 320px 크기와 상세 열기, 광고 취소 보존, 원본 복구를 확인합니다. 새 디자인이 보이지 않으면 새로고침 후 열린 온점 탭/홈 화면 앱을 모두 닫고 다시 여세요. 기존 서비스 워커는 열린 창이 끝난 뒤 새 버전을 적용합니다.

## 온실 UI 개편 — 2026-11-04

홈의 긴 카드 흐름을 온실 장면과 하단 행동 패널로 바꿨습니다. 현재 할 일이 있으면 바로 이어 하고, 없으면 생각 입력이 주 버튼입니다. 계절에 따른 빛·창문·화분 받침대, 곡면 화분과 그림자는 자체 SVG로 그렸으며 외부 이미지나 3D 엔진을 로드하지 않습니다. 정원은 카드 테두리 대신 세 줄의 선반에 3×3 화분을 놓고 기존 좌우 넘기기를 유지합니다.

실행 화면의 주 행동은 완료 하나이며 나중에/작은 단계는 보조 행동입니다. 입력·검토·꽃 상세는 하단 시트로 열리고 닫기 버튼/배경/Android 뒤로 가기로 닫습니다. 시트를 닫았다 다시 열면 세션 내 초안을 유지하며 앱 재실행까지 초안을 보관하지는 않습니다. 개화는 별도 조명 배경과 창작 꽃말로 표현합니다. 모션 감소 설정을 유지하고 추가적인 반복 애니메이션은 사용하지 않습니다.

디자인 판단과 조사 제약은 [docs/design-review.md](docs/design-review.md)에 기록했습니다. 최신 App Store/공식 사이트 화면 직접 조사는 네트워크 정책 차단으로 미완료입니다. 디자인을 다른 앱의 최신 화면을 검증해 복제한 결과로 표현하지 않습니다. 로컬 검증은 320×640·390×844·데스크톱에서 수행하며 실물 iPhone/Safari와 네이티브 접근성·키보드 QA는 남아 있습니다.
