# 온점.

생각을 자유롭게 내려놓고 하나씩 실제 행동으로 옮기면 어느새 꽃이 피어나는 한국어 실행 앱입니다. 치료·진단, 집중 타이머, 연속 출석, 식물 시들기, 미완료 페널티는 없습니다.

React Native / Expo 모바일 앱과 원본을 바탕으로 한 HTML/PWA가 순수 도메인 로직을 공유합니다. 첨부받은 `onjeom-codex-ready.zip`은 **`prototype/`에 모든 파일을 바이트 그대로 보존**했습니다. `prototype-source.json`의 SHA-256을 자동 테스트로 검증합니다. 원본 지침은 루트 `AGENTS.md`에도 적용합니다.

## 실행

Node.js 22.13 이상, npm. 검증 환경은 Linux / Node 24.19 / Expo SDK 54입니다.

```sh
npm ci
npm start                  # Expo 개발 서버
npm run ios                # 호환 iOS 시뮬레이터에서 열기 (macOS/Xcode 필요)
npm run android            # Android 에뮬레이터/연결 기기에서 열기
npm run build:ios          # 네이티브 개발 빌드 생성·실행 (macOS/Xcode 필요)
npm run build:android      # 네이티브 개발 빌드 생성·실행 (Android SDK 필요)
npm run web                # 통합한 원본 기반 웹, 기본 포트 4173
```

Expo SDK 54와 호환되는 Expo Go 또는 개발 빌드를 사용합니다. 최신 Expo Go의 SDK 지원 범위와는 다를 수 있습니다. 기존 검증된 SDK 54를 유지했으며 이번 통합에서 최신 SDK 업그레이드나 스토어 배포는 수행하지 않았습니다. 모바일 SQLite는 iOS·Android 전용이고, 브라우저에서는 `npm run web`을 사용합니다.

`npm run prototype:original`은 **수정 없는 보존본**을 실행합니다. 원본에는 모달의 인라인 `stopPropagation()` 때문에 내부 버튼이 문서 이벤트 처리기로 전달되지 않는 문제가 있습니다. 기본 `npm run web`은 이 문제를 고친 실행용 `web/app.mjs`를 사용합니다. 원본 CSS·일러스트·도메인은 유지하고 검토·수정·순서 변경과 백업 전환을 보완했습니다. 두 서버의 기본 포트가 같으므로 동시에 실행하지 마세요.

## 제품 흐름과 원본 규칙

- **생각 입력 → 사용자 검토**: 원본의 한국어 규칙 기반 `splitThought`를 공유합니다. AI가 아닙니다. 분리 결과의 수정·제외·추가·순서 변경 후 확정하며, 검토한 제목을 다시 파싱하지 않습니다. 입력하지 않은 기한·우선순위·예상 시간을 추가하지 않습니다.
- **한 번에 하나**: 완료, 나중에, 작은 단계로 나누기. 나중에는 원본처럼 씨앗 보관함으로 이동하고 이어하면 활성 목록 끝에 돌아옵니다. 모바일 ‘오늘’의 할 일 관리에서 제목 수정·삭제·순서 변경도 가능합니다.
- **4개 완료 → 1송이 개화**: 원본 12종과 창작 문구를 유지합니다. 개발용 확률은 일반 96.5%, 달빛·오로라 합계 3%, 금빛 0.5%. 무료와 PLUS가 같은 추첨을 사용합니다.
- **시즌**: 원본대로 크리스마스 12/18–26, 할로윈 10/24–11/1, 새해 12/30–1/3. 기간 중 시즌 품종 확률은 24%이며, 항상 시즌 품종만 나오는 구조가 아닙니다. 날짜는 원본처럼 기기 현지 날짜를 사용합니다.
- **추석은 아직 비활성**: `src/season-calendar.mjs`에 출처가 검토된 연도별 공식 양력 일정이 있을 때만 활성화됩니다. 한국천문연구원 접근이 현재 네트워크 정책에서 HTTP 403으로 차단되어 공식 데이터를 검증하지 못했습니다. 음력 추정이나 임의 날짜를 넣지 않았습니다. 테스트의 가상 일정은 실제 운영 데이터가 아닙니다.
- **꽃말은 온점. 창작 문구**: 전통 꽃말/식물학적 사실로 표시하지 않습니다. 등록 전에도 열람·텍스트 카드 저장/공유가 무료입니다. 웹은 무료 카드 문구 복사를 제공합니다. 모바일 네이티브 공유는 실기기에서 추가 검증해야 합니다.
- **정원·도감**: 계절 배경과 모든 꽃의 기억의 정원, 품종+색상별 도감, 개화일·완료 행동 기록. 미등록 꽃도 계속 보관합니다. 새 꽃에는 최근 네 완료 행동을 기록하고, 원본에서 가져온 꽃에는 원래 있던 `originTask`만 보여 줍니다. 없는 과거 기록을 만들어 내지 않습니다.

## 광고·PLUS·AI 경계

실제 광고/결제 SDK·구매 권한 검증은 없습니다. 모든 관련 화면에 테스트 모드를 표시하고 비용을 청구하지 않습니다. 무료 사용자가 **새 품종+색상 조합을 최초 등록하기로 선택한 순간에만** 보상 테스트를 제안합니다. 동일 조합은 광고 없이 등록하며 PLUS 데모도 우회합니다. 취소·미제공은 미등록 꽃을 유지합니다. 개화와 꽃말 카드에는 광고가 없습니다.

실제 SDK 연결 전에는 테스트 성공 버튼을 실제 보상 증거로 사용하지 마세요. AI 서버는 연결하지 않았습니다. `src/separator.mjs`의 비동기 `separate(text)`를 향후 동의·서버 인증·오류 처리를 갖춘 어댑터로 교체할 수 있습니다. 작업 원문을 광고/분석에 보내지 않습니다.

## 원본 웹 기록을 모바일로 옮기기

1. 원본을 사용하던 **같은 브라우저·호스트·포트**에서 통합 웹을 실행합니다. 저장 키 `onjeom.local.v1`을 그대로 사용하므로 기존 웹 기록을 이어서 볼 수 있습니다.
2. 보관함의 ‘백업 내보내기 · 모바일로 옮기기’를 열거나 `/transfer/` 경로를 엽니다.
3. ‘이 브라우저 기록 내보내기’로 JSON을 저장하고 모바일 설정에서 그 파일을 복원합니다. 웹의 원본 저장소는 변경하지 않습니다.

다른 사이트/브라우저의 localStorage는 읽을 수 없습니다. 다른 호스트에서 사용한 원본은 해당 사이트의 기록 JSON을 확보해 전환 화면의 파일 선택으로 변환해야 합니다. 기기 간 자동 동기화나 계정 로그인은 없습니다. 백업은 개인 생각을 포함하는 **암호화하지 않은 JSON**이므로 안전한 곳에 보관하세요.

## SQLite 및 마이그레이션

`onjeom.db`는 WAL·FULL synchronous·배타적 트랜잭션을 사용하며 저장 성공 후 UI를 반영합니다. DB `user_version`은 0→1(상태 테이블)→2(메타데이터)→3(원본 공유 스키마)으로 이동합니다.

지원하는 입력은 원본 웹 v1 JSON, 앞서 만든 모바일 v1/v2 JSON 백업, 현재 v3 백업입니다. 원본의 생각 원문·작업 ID/순서·미완료 씨앗·꽃 ID/색상/창작 문구/날짜/등록 여부를 유지합니다. 앞선 모바일의 다른 꽃·색상도 `legacy-*` 변이로 보관하며 새 추첨에는 원본 규칙만 씁니다. v2에 없던 생각 원문이나 정확한 생성 시간은 새로 만들지 않습니다.

버전·ID·날짜·종류·진행 수를 검사해 손상/미래 버전 데이터를 자동 초기화하지 않습니다. 실패한 마이그레이션은 롤백하고 잘못된 복원은 기존 데이터를 바꾸지 않습니다. 손상된 구버전 payload도 시작 오류 화면에서 **유효 백업을 선택하고 복원을 확인한 경우에만** 교체합니다. DB 파일 자체 손상·누락을 모두 수리하는 기능은 아니므로 기기 밖 백업이 필요합니다.

복원은 현재 기기 전체 상태를 교체합니다. 전체 삭제는 빈 상태 저장 후 WAL 체크포인트/VACUUM을 실행합니다. 플래시나 OS 백업까지의 보안 삭제를 보장하지 않으며 내보낸 파일은 별도 삭제해야 합니다. 앱 중단 시 확정한 작업/꽃/설정은 복원하지만 미확정 입력 초안은 복원하지 않습니다.

## 검증

```sh
npm test                   # 원본 11개 포함 총 31개 도메인/SQLite/무결성 테스트
npm run test:original       # 첨부 원본 테스트 11개 그대로 실행
npm run test:browser        # Chromium 사용자 흐름 4개
npm run check              # TypeScript
npm run format:check       # 원본 폴더는 포맷 대상에서 제외
npm run export             # iOS·Android Hermes 번들, 설치 파일은 아님
```

Chromium 기본 경로는 `/usr/bin/chromium`이며 `CHROMIUM_PATH`로 변경할 수 있습니다. 자세한 실행 결과와 미실행 항목은 `VALIDATION.md`를 확인하세요. 네이티브 런타임·파일 공유/선택·접근성·스토어 배포는 실기기 QA가 남아 있습니다. Node SQLite 파일 재오픈 검증을 실제 모바일 재부팅 검증으로 간주하지 않습니다.

## 주요 파일과 남은 작업

`prototype/`는 수정 없는 첨부 원본, `src/logic.mjs`는 그 도메인을 재노출하는 공유 진입점, `src/mobile-domain.mjs`는 검토/스키마/백업 확장입니다. `src/legacy-mobile.mjs`는 이전 모바일 데이터 읽기 전용이고 새 작업 규칙으로 사용하지 않습니다. `App.tsx`는 Expo UI, `src/storage.mjs`는 SQLite, `web/`는 원본 기반 실행 UI·전환 도구입니다.

남은 작업: 공식 추석 일정 검증·등록, 실기기 QA와 큰 글꼴/VoiceOver/TalkBack, 품종별 일러스트(현재 공통 모티프), 긴 기록 목록 가상화, 최신 Expo SDK 업그레이드/개발 빌드 호환성 확인, 실제 광고/결제 서버 검증과 스토어 설정. 원본 아카이브의 설명은 당시 상태를 기록하므로 현재 기능은 이 README를 기준으로 봅니다.
